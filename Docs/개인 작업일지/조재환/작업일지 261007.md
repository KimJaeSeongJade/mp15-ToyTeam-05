## 막히거나 헤매었던 부분
- 협동 모드에서 데스크가 정해진 위치로 이동하는 기능을 구현하면서 목표 위치를 Transform 으로 정해주는 방식을 사용하는데 원하는 위치의 월드 좌표를 직접 확인해 입력하려 했지만 오브젝트의 중심점과 실제로 맞추고 싶은 위치가 달라 내가 원하는 정확한 위치를 파악하고 맞추기 어려웠다
- 이때 기존 데스크를 원하는 위치에 복사한 뒤 자식 오브젝트를 제거하고 비어있는 Transform만 남겨 목표 위치로 사용하는 방법을 생각해 사용하여 내가 원하는 작동방식대로 움직일 수 있게 구현해 성공했다

- 기존에 정상적으로 작동하던 주문서 UI를 오브젝트 풀 방식으로 변경하면서 테스트 과정에서 기존과 다르게 동작하는 문제를 발견했다. 처음에는 오브젝트 풀로 변경하는 과정에서 내가 리스트를 잘못 지우고 있다 생각해 오브젝트 풀링 작업한 코드를 제거하고 기존 방식으로 되돌려 다시 테스트해봤다.
- 하지만 기존 방식에서도 처음에는 문제가 없지만 나중에 나오는 문제였던 것을 확인했고 기존부터 문제가 있었다는 것을 알게 되었다
- 앞으로는 리팩토링 전에 먼저 로직을 자세히 확인한 후 변경해야겠다. 그 뒤로는 다른 작업을 하느라 오브젝트 풀링을 적용을 못했다

## 개인 회고록
- 주문서 UI를 오브젝트 풀 방식으로 변경하면서 문제가 발생해, 원인을 오브젝트 풀이라고 생각하고 구현했던 코드를 전부 삭제했다. 하지만 기존 방식으로 다시 테스트해보니 기존 로직에서도 문제가 발생하고 있었다. 기존 기능이 정말 정상적으로 동작하는지 먼저 확인한 뒤 리팩토링을 진행했어야 했는데, 원인을 충분히 확인하지 않고 작업한 코드를 지워버린 점이 아쉬웠다.

- 이번 경험을 통해 기존 기능을 수정하거나 새로운 구조로 변경할 때는 변경 전 상태를 먼저 테스트하고 기준이 되는 정상 동작을 확인하는 과정이 중요하다는 것을 느꼈다. 다음부터는 문제가 발생했다고 바로 코드를 되돌리기보다, 기존 버전과 변경한 버전을 비교하면서 원인을 먼저 좁혀봐야겠다.

- 오늘은 내가 담당한 기능 중 플레이어와 연결해서 테스트해야 하는 부분이 많았는데, 플레이어 기능이 아직 완성되지 않아 작업을 진행하지 못하고 기다리는 시간이 생겼다. 팀 프로젝트이기 때문에 경험할 수 있었던 일인것 같다. 다른 팀원의 기능 완성 여부나 중요도를 파악해 비는 시간이 없도록 작업 순서를 잘 짜야겠다고 생각했다.
