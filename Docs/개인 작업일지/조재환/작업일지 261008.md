## 막히거나 헤매었던 부분
1. 사운드 설정 기능 구현

- Title 화면에 Setting UI를 추가하여 BGM과 SFX의 볼륨을 조절할 수 있도록 구현하려 했음.
- 관련 자료를 찾아보는 과정에서 처음 접하는 AudioMixer와 데시벨(dB) 개념을 알게 되었음.
- 기존에 사용하던 AudioSource 방식과 달리 AudioMixer를 이용한 볼륨 조절 방식에 대한 이해가 부족하여 아직 구현하지 못한 상태임.

2. 특별 주문의 플레이어 이동 방향 반전 문제

- 처음에는 플레이어의 이동 방향에 -1을 곱하는 방식으로 반전 효과를 구현하려 했음.
- 하지만 플레이어의 이동 방향을 Update에서 매 프레임 갱신하고 있어, -1을 곱해도 다음 프레임에 원래 방향으로 돌아가는 문제가 발생했음.
- 이를 해결하기 위해 특별 주문이 적용될 때 별도의 값을 더하고 빼는 방식으로 변경했음.
- 처음에는 Player1의 이동 방향을 반전할 때 +1, Player2는 +4를 적용하고, 값이 1 또는 4인지 확인하는 방식으로 구현했음.
- 하지만 팀장님께서 "두 플레이어가 모두 특별 주문을 제출하면?", "Player1이 특별 주문을 두 번 제출하면?"이라는 질문을 하셨고, 기존 방식으로는 이러한 상황을 처리하기 어렵다는 것을 알게 되었음.
- 팀장님의 조언으로 나눗셈(/)과 나머지 연산(%)을 활용하는 방법을 알게 되었고, 기존의 +1, +4 방식을 유지하면서도 여러 상황에 대응할 수 있도록 수정했음.

## 개인 회고록
- 특별 주문으로 플레이어의 이동 방향을 반전시키는 기능을 구현하면서 발생할 수 있는 상황을 너무 단순하게 생각하고 코드를 작성했던 것 같다.
- 처음에는 Player1과 Player2를 구분하여 반전시키는 것만 생각했는데, 팀장님께서 두 플레이어가 동시에 특별 주문을 제출하거나 한 플레이어가 여러 번 제출하는 경우를 질문하셨을 때 미처 생각하지 못한 상황이라는 것을 깨달았다.
- 팀장님께서 나눗셈과 나머지 연산을 활용하는 방법을 설명해 주셨을 때는 바로 이해하지 못했지만, 직접 값을 하나씩 대입하고 동작 순서를 정리해 보면서 원리를 이해할 수 있었다.
- 단순한 사칙연산과 나머지 연산만으로 여러 상황을 처리할 수 있다는 점이 인상 깊었고, 어떻게 이런 방법을 생각해 낼 수 있었을까 하는 생각이 들었다.
- 이번 경험을 통해 기능이 정상적으로 작동하는 것뿐만 아니라, 여러 상황에서 어떤 결과가 발생할지도 미리 생각하는 것이 중요하다는 것을 느꼈다.
- 앞으로는 코드를 작성하기 전에 발생할 수 있는 예외 상황을 먼저 생각해 보고, 하나의 상황에만 맞춰 구현하지 않도록 노력해야겠다고 생각했다.
