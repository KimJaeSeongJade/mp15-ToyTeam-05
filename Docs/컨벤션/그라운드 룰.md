# 그라운드 룰

## 코어 타임

- **12 : 00 ~  23 : 00**
- 기본적으로 작업 가능 여부 상관없이 연락은 확인하기.
- 예외의 상황이 생길시엔 미리 알리기.

## 브랜치

- **Main 브랜치에서 작업 X**
- **[ 영문 이름_ 진행할 작업 ]** 한 눈에 확인가능하도록 **단어**로 표현한다.
- 작업 후 **해당 작업 완료 여부와 관계없이** 컴퓨터 종료 전 반드시 **PR 요청** 올린다.
- **PR**은 **저녁 22시까지** 보낸다.

## PR 확인

- PR 확인은 기본적으로 **팀장**이 맡아서 한다.( 예외의 상황은 늘 있습니다. 충돌없이 단순 Marge 이면서 팀장님의 업무가 과도한 경우- 팀장님은 팀원 한 분을 지정하여 PR 승인 업무를 맡길 수 있습니다. )
- PR 요청시 작업 내역은 확실하게 기입한다. ( 양식 가능하면 준비해보겠습니다_ 작업파트/ 내용/ 오류여부등 )
- PR 완료시 팀장님은 메신저에 해당 내용 간결하게 안내 남긴다.

## 작업 막혔을 때

- 30분 이상 막힌 부분에서 헤매고 있을 시 메신저를 통해 도움을 요청한다.
- 막힌 상황에 대해서는 가능한 명확하게 설명한다.

## 공유 문서 플랫폼

- 간단한 기획 → 구글 드라이브
- 팀 내 규칙 컨벤션 → 깃허브 저장소
- 회의록 → 깃허브 저장소
- 업무리스트 → 구글 시트
- 개인별 일정관리 캘린더 → 구글시트

- 시트-링크 : 모든 기획 관련 문서는 '기획문서 드라이브'에 업로드 합니다. 파일명은 직관적으로 적고 _날짜를 필수로 적습니다.

## 수정사항이 생겼을 때

- 처음 기획된 것과 다른 **수정사항**이 생겼을 시 반드시 **모두에게 공유**합니다.

  - 짧은 내용이라면 공지방에 내용 정리하여 공유, 내용이 많다면 문서화하여 구글 시트에 링크로 걸고 슬랙에 공지합니다.

- **다른 사람 작업물에 대해 수정**하고 싶은 사항이 생겼을때는 반드시 **해당 작업자와 논의 후** 결정합니다.

  -수정 해야하는 타당한 이유가 있어야하며 해당 작업자를 설득할 수 있어야합니다.

## 기타

- 해야할 일이 많다면 **우선순위**를 확실하게 정하고 **한 번에 한 가지 일**을 합니다.

- 한 사람이 2-3가지 일을 동시에 작업함으로서 일이 늦어지면 연결된 다른 사람 작업 진행도 함께 늦어              집니다. 또한 분담 가능한 일도 분담 할 수 없게 됩니다.
