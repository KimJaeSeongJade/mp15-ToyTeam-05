# [Git Hub 작업 프로세스]

|  | 플랫폼 | 할 일 |  깃허브 칸반보드 |
| --- | --- | --- | --- |
| Step 1 | 구글 스프레드 시트 | 시작 할 작업 확인 - 작업 현황 ‘작업 중’으로 변경 |  |
| Step 2 | 깃 허브 | 들어갈 작업 이슈 업로드 | TODO |
| Step 3 | 깃 허브 데스크 | main 패치 후 당기기 → 새 브랜치 생성 |  |
| Step 4 | 유니티 | 작업 |  |
| Step 5 | 깃허브 데스크 | PR 올리기 | In Progress |
| Step 6 | 깃 허브 | PR 승인 → 브랜치 삭제 | Done |
| Step 7 |  | 데일리 체크인 / 개인 작업일지 작성 |  |

### 칸반 보드 위치 : Git Hub - Projects

---

### Step 1

- 구글 스프레드 시트 → 작업 시트를 확인합니다.
- 시작할 작업을 확인합니다. 작업자 이름에 본인 이름이 없을 경우 토글을 내려 변경합니다.
- 상태를 ‘작업 중’으로 변경합니다.

### Step 2

- 깃 허브 → 이슈
- new Issue 를 생성합니다.
- 필요시 승인자/ 라벨을 설정합니다.
- 구글 작업 시트를 참고하여 아래 양식으로 이슈 제목을 기입합니다.

>> **[ 게임 오브젝트 단위의 타입 기입 ] 세부 내용 기입**

- ex) [Player]  프리팹 생성
- 칸반보드 TODO에 해당 내용이 올라갑니다.

### Step 3 ~ Step 4

- 깃 허브 데스크 main에서 최신 정보를 패치 후 당겨옵니다.
- 새 브랜치를 아래 양식으로 생성합니다.

>>   **영문 이름_ 진행할 작업**  

- 본 작업에 들어갑니다. 브랜치 생성 전에 유니티 파일을 먼저 생성하지 않습니다.

## Step 5

- 기능 하나의 작업이 마무리되면 PR을 올립니다.
- **작업 완료 여부와 관계 없이 저녁 22시 전에 반드시 PR을 올립니다.**
- PR 세부 양식은 양식문서를 참고합니다.
- PR을 올리면 해당 이슈는 칸반보드의 In Progress로 자동으로 옮겨갑니다.

## Step 6

- PR 승인이 완료 되면 ‘구글 시트- 상태’ 를 ‘완료’로 변경합니다.
- PR 승인이 완료 되면 해당 **브랜치는 반드시 삭제**합니다. 다음 작업에 이어서 사용하지 않습니다.
- PR 승인이 완료되면 **칸반보드의 Done** 으로 자동으로 옮겨갑니다.

## Step 7

- 하루 작업이 끝나면 **‘구글 작업 시트 - 링크 - 데일리 체크인’** 을 작성합니다.
- ‘깃 허브 - Docs - 개인 작업일지- 본인 이름’ 폴더에서 개인 작업일지를 작성합니다.
- 작업일지 양식은 만들어 두었으나 자유롭게 커스텀하여 사용하셔도 됩니다.
